## ColBERT: Multi-Vector Retrieval Model

#### 1. 离线索引 (Offline Indexing)

> 目标：将整个文档集合预处理成可快速检索的向量索引，供在线查询时使用。

- **1.1 文档分词 (Tokenization)**
  - 对集合中的每篇文档 `d`，使用 BERT 的 WordPiece 分词器进行分词，得到 token 序列 `[CLS] [D] d_1 d_2 ... d_n`。
  - 其中 `[D]` 是特殊标记，用于区分文档序列（区别于查询序列的 `[Q]`）。

- **1.2 BERT 编码 (BERT Encoding)**
  - 将 token 序列输入 BERT 模型，获得每个 token 的上下文嵌入向量（hidden states）。
  - 由于 BERT 是双向 Transformer，每个 token 的向量都包含了整个文档的上下文信息。

- **1.3 线性投影 (Linear Projection)**
  - 将 BERT 输出的每个 token 向量（维度 = 768）通过一个无激活函数的线性层，投影到更低维的空间（维度 `m`，通常 `m = 128`）。
  - 这一步的目的是**控制存储空间**：缩小每个向量的维度，减少索引体积。

- **1.4 L2 归一化 (L2 Normalization)**
  - 对投影后的每个向量进行 L2 归一化，使其模长为 1。
  - 这使得后续的**余弦相似度**计算等价于**点积 (dot product)**，极大简化了计算。

- **1.5 过滤标点符号 (Punctuation Filtering)**
  - 过滤掉对应于标点符号（如 `. , ! ?` 等）的 embedding 向量。
  - 目的：减少每篇文档的存储向量数量，因为标点符号对语义匹配几乎没有贡献。

- **1.6 存储文档向量 (Store Document Embeddings)**
  - 将每篇文档 `d` 处理后的多向量集合 `E_d = {v_1, v_2, ..., v_M}` 保存到磁盘。
  - 存储时通常使用 16-bit 或 32-bit 浮点数（根据精度/空间权衡）。
  - 最终形成一个**文档向量表**：`doc_id -> list of vectors`。

- **1.7 (可选) 构建向量索引 (Build Vector Index for End-to-End Retrieval)**
  - 如果希望 ColBERT 直接进行端到端检索（而非仅做重排序），则需要将所有文档的 token 向量统一索引到 **Faiss** 这类向量相似度搜索引擎中。
  - Faiss 会构建一个**倒排索引 (Inverted Index)** 或 **IVFPQ 索引**，以便在线检索时通过近似最近邻搜索 (ANN) 快速定位候选文档。

---

#### 2. 在线查询处理 (Online Query Processing)

- **2.1 查询分词与编码 (Query Tokenization & Encoding)**
  - 对输入查询 `q` 进行分词，得到 token 序列 `[CLS [Q]] q_1 q_2 ... q_l`。
  - **查询增强 (Query Augmentation)**：如果查询长度小于预设值 `N_q`（通常为 32），则在末尾填充 `[MASK]` 标记至长度为 `N_q`。这些 `[MASK]` 向量会作为可学习的“软扩展”机制，帮助模型生成额外的查询语义向量。
  - 将序列输入 BERT，通过线性投影和 L2 归一化，得到查询的多向量表示 `E_q = {u_1, u_2, ..., u_N}`。

- **2.2 候选文档获取 (Candidate Retrieval)**
  - **情况A - 仅做重排序 (Re-ranking)**：
    - 使用传统检索模型（如 BM25）快速召回 Top-`k`（通常 `k = 1000`）篇候选文档。
    - 从磁盘加载这些文档的预计算向量表示。
  - **情况B - 端到端检索 (End-to-End Retrieval)**：
    - 对于查询中的每个向量 `u_i`，使用 Faiss 索引在全文档集合中进行近似最近邻搜索，分别召回 Top-`k'` 个最相似的文档 token 向量。
    - 将这些 token 向量按文档 ID 分组，得到一组候选文档列表（去重后通常远少于全量文档）。

- **2.3 延迟交互打分 (Late Interaction Scoring)**
  - 这是 ColBERT 的核心操作。对于查询向量集合 `E_q` 和某篇文档向量集合 `E_d`，计算相关性分数：
  
  $$
  S_{q,d} = \sum_{i=1}^{|E_q|} \max_{j=1}^{|E_d|} \left( u_i \cdot v_j^T \right)
  $$
  
  - **步骤拆解**：
    1. 对查询中的**每个**向量 `u_i`，计算它与文档中**所有**向量 `v_j` 的点积（由于 L2 归一化，点积 = 余弦相似度）。
    2. 取这组点积中的**最大值 (Max)**，代表该查询 token 在文档中找到的最佳匹配程度。
    3. 将所有查询 token 的 Max 值**求和 (Sum)**，作为该文档的最终相关性分数。
  - **特点**：这一交互发生在 BERT 编码**之后**（即“延迟”），因此文档向量可预计算。同时，MaxSim 保留了词粒度的细粒度匹配，相比单向量模型精度更高。

- **2.4 排序与返回 (Sort & Return)**
  - 对所有候选文档按分数 `S_{q,d}` 从高到低排序。
  - 返回 Top-`K`（如 Top-10）作为最终检索结果。

---

#### 3. 核心优势

| 维度 | 传统 BERT Cross-Encoder | ColBERT (延迟交互) |
| :--- | :--- | :--- |
| **文档编码** | 每次查询都要重新编码，无法预计算 | **离线预计算并存储**，查询时直接加载 |
| **查询编码** | 需与每个文档拼接，编码一次只能算一个文档 | 编码一次，可与所有候选文档打分 |
| **交互方式** | 早期交互（BERT 内部全连接 Attention） | 延迟交互（MaxSim 点积） |
| **速度** | 极慢（秒级/查询） | 快（毫秒级/查询） |
| **精度** | 最高（SOTA） | 接近 SOTA，远超单向量模型 |


## ColBERTv2: Multi-Vector Retrieval Model（升级版）

> ColBERTv2 在保留原始 ColBERT "延迟交互 (Late Interaction)" 架构的基础上，重点解决了两个核心痛点：
> 1. **索引过大**（原始 ColBERT 需 154 GiB 存储 900 万文档）；
> 2. **训练不充分**（原始模型仅依赖 BM25 的粗粒度信号）。
>
> 它通过引入**残差压缩 (Residual Compression)** 和**去噪监督 (Denoised Supervision)**，在将索引空间缩小 **6-10 倍**的同时，检索精度（MRR@10）从 34.9 提升至 **39.7**，达到业界领先水平。

---

#### 1. 训练策略：去噪监督 (Denoised Supervision)

> 核心思想：不再仅仅依赖人工标注的"相关/不相关"标签，而是向一个强大的"教师模型"学习精细的排序偏好。

- **1.1 教师模型蒸馏 (Cross-Encoder Distillation)**
  - 引入一个计算昂贵但精度极高的 **交叉编码器 (Cross-Encoder)**，例如 22M 参数的 MiniLM，作为"教师"。
  - 对于每个训练查询，先用一个初步的 ColBERT 模型召回 Top-500 篇候选文档。
  - 用"教师模型"为这 500 篇文档逐一打分，生成连续的、包含细微差异的**软标签 (Soft Labels)**（例如：文档 A 得 0.98 分，文档 B 得 0.75 分，文档 C 得 0.12 分）。
  - ColBERTv2（学生）通过 **KL 散度损失 (KL-Divergence Loss)** 来拟合这些软标签，从而学习到教师模型捕捉细微相关性的能力。

- **1.2 难负例与批量负例 (Hard & In-batch Negatives)**
  - **难负例 (Hard Negatives)**：特意选取那些与查询语义相似、但实际并不相关的文档作为负例，迫使模型学习更精细的判别边界。
  - **批量负例 (In-batch Negatives)**：利用同一训练批次中其他查询的正样本文档，作为当前查询的额外负例，极大丰富了负例池，增强模型泛化能力。

---

#### 2. 离线索引：残差压缩 (Residual Compression)

> 核心思想：不再存储全精度的浮点数向量，而是存储"向量到聚类中心的距离残差"，并对残差进行极低比特量化。

- **2.1 聚类中心选择 (Centroid Selection)**
  - 从文档集合中**随机采样**一部分文档，计算每个文档的所有 Token 向量。
  - 对这些采样向量执行 **K-Means 聚类**，生成一组固定的**聚类中心 (Centroids)** `C`（例如 MS MARCO 中生成约 26 万个中心；C是超参数）。
  - 这些中心将作为后续所有向量压缩的"参照坐标系"。

- **2.2 残差计算与量化 (Residual Computation & Quantization)**
  - 对文档中的**每一个** Token 向量 `v`（128 维浮点数）：
    1. 在聚类中心 `C` 中，找到离 `v` 最近的中心 `C_t`。
    2. 计算**残差 (Residual)**：`r = v - C_t`（同样是 128 维）。
    3. **量化残差**：对残差向量 `r` 的**每一个维度**进行压缩，仅用 **1-bit 或 2-bit** 来表示该维度的数值。
  - **最终存储内容**：
    - **聚类中心 ID**（占 4 字节）。
    - **量化后的残差**（占 `1 bit × 128 = 16 字节` 或 `2 bit × 128 = 32 字节`）。
  - **空间对比**：原始需存储 `16 bit × 128 = 256 字节`/向量，现仅需 **20~36 字节**/向量，压缩率达 **6-10 倍**。

- **2.3 构建倒排索引 (Inverted Index)**
  - 为了在检索时快速定位，系统构建一个倒排索引，映射关系为：`聚类中心 ID -> 归属于该中心的所有文档 Token 列表`。
  - 这使得查询时无需扫描全库，只需访问查询向量附近的少数几个聚类中心。

---

#### 3. 在线检索：两阶段打分 (Two-Stage Retrieval)

> 核心思想：先用"便宜"的近似向量筛掉 99% 的不相关文档，再用"昂贵"的原始精确向量对少数候选进行精排。

- **3.1 阶段一：近似候选生成 (Approximate Candidate Generation)**
  - 对查询的每个 Token 向量，找到最近的 `n_probe` 个聚类中心。
  - 通过倒排索引，快速定位到这些中心下的文档 Token。
  - **解压 (Decompression)**：根据存储的"中心 ID"和"量化残差"，通过公式 `\tilde{v} = C_t + 反量化(残差)` **近似重建**出原始向量（虽有精度损失，但计算极快）。
  - 利用这些近似向量与查询向量进行 MaxSim 计算，从全库中筛选出得分最高的 `n_candidate` 篇（如几千篇）文档，进入下一阶段。

- **3.2 阶段二：精确重排 (Exact Re-ranking)**
  - 从磁盘**加载**第一阶段筛选出的少量候选文档的**完整、未压缩的原始浮点数向量**。
  - 执行标准的 ColBERT **延迟交互 (Late Interaction)** 打分：
    
    $$
    S_{q,d} = \sum_{i=1}^{|E_q|} \max_{j=1}^{|E_d|} \left( u_i \cdot v_j^T \right)
    $$
    
    （此时使用的 `u_i` 和 `v_j` 均为未经压缩的精确向量）
  - 得到每篇文档的最终精确相关性分数。

- **3.3 排序与返回**
  - 按精确分数从高到低排序，返回 Top-K 结果给用户。

---

#### 4. ColBERTv2 核心成果总结

| 维度 | 原始 ColBERT | **ColBERTv2 (升级后)** |
| :--- | :--- | :--- |
| **索引空间 (MS MARCO)** | **154 GiB**（部署困难） | **16 ~ 25 GiB**（缩小 6-10 倍，可实际落地） |
| **核心压缩技术** | 无（存储全精度 256 字节/向量） | **残差压缩 (残差量化 + 倒排索引)**，仅存 20-36 字节/向量 |
| **检索流程** | 一次性精确 MaxSim 计算 | **两阶段检索**（近似粗筛 → 精确重排） |
| **训练方式** | 简单 BM25 三元组 | **知识蒸馏 (KL散度) + 难负例 + 批量负例** |
| **检索精度 (MRR@10)** | ~34.9 | **~39.7**（显著提升，达到 SOTA） |
| **查询延迟** | ~100 毫秒 | **~50-250 毫秒**（视参数配置而定） |
| **适用场景** | 学术研究、小规模验证 | **工业级大规模部署**（兼顾速度、精度与存储成本） |


## PLAID: Performance-optimized Late Interaction Driver（高性能检索引擎）

---

#### 1. 核心动机与关键观察（Motivation & Insights）

在深入技术细节前，PLAID 的设计基于两个至关重要的实验观察：

- **观察 1：仅凭"质心"即可锁定高分文档（图 3）**
  - 在 ColBERTv2 的压缩体系中，每个 Token 向量被表示为 **"质心 ID（Centroid ID）"** + **"残差（Residual）"**。
  - 实验发现，如果**完全不使用残差**，仅利用每个文档的"质心 ID 列表（Bag of Centroids）"进行检索，在召回 Top-1000 文档时，若候选集扩大到 10 倍（即 10000 篇），其对原始 ColBERTv2 精确结果的**召回率可达 99% 以上**。
  - **结论**：残差主要负责"精排"，而"质心"足以胜任"粗筛"，无需对每个候选文档都进行昂贵的残差解压。

- **观察 2：查询仅关注极少数"重要"质心（图 4）**
  - 对于特定的查询，其向量与所有质心的相似度得分分布极不均衡：只有**极少数（长尾）质心**拥有非常高的得分，而绝大多数质心的得分趋近于零。
  - **结论**：在计算质心交互得分时，可以安全地丢弃那些低得分的质心，从而大幅削减计算量。

---

#### 2. 离线索引优化：倒排列表重构（Inverted List Rebuild）

> PLAID 改变了 ColBERTv2 的倒排索引存储结构，从"存储嵌入 ID"转变为"存储文档 ID"。

- **原始 ColBERTv2 倒排**：`质心 ID -> 归属于该质心的所有 Token 嵌入 ID 列表`（查询时需先找 Embedding，再反查 Document，且需处理巨量 64 位 ID）。
- **PLAID 倒排**：`质心 ID -> 归属于该质心的所有 文档 ID (Passage ID) 列表`。
- **优势**：
  - 文档总数远少于 Token 嵌入总数（通常少一个数量级），因此倒排列表体积大幅缩小。
  - 只需存储 32 位整数（int32）即可表示文档 ID，无需 64 位。
  - **实测数据**：在 MS MARCO v2（1.4 亿文档）上，倒排索引从 **71 GB 降至 27 GB**，空间节省约 **2.7 倍**。

---

#### 3. 在线检索：四阶段渐进式筛选流水线（The 4-Stage Pipeline）

> PLAID 的核心思想是**层层递进，逐步减少候选集**，仅在最后阶段对极少数文档进行完整的残差解压和精确计算。其流程如图 5 所示：

- **阶段 1：候选生成（Candidate Generation）**
  - **输入**：查询矩阵 $Q$，预计算的质心向量矩阵 $C$。
  - **计算**：执行矩阵乘法 $S_{c,q} = C \cdot Q^T$，得到每个查询 Token 与所有质心的相似度得分。
  - **操作**：根据超参数 `nprobe`（即每个查询 Token 访问的质心数），通过倒排索引拉取所有相关文档，构成**初始候选集**（规模较大，例如数万篇）。
  - **特点**：此阶段**不加限制**（不像 ColBERTv2 用 `ncandidates` 强制截断），因为后续阶段会低成本过滤。

- **阶段 2：质心剪枝（Centroid Pruning）**
  - **核心**：利用观察 2，剔除"不重要"的质心。
  - **操作**：设定阈值 $t_{cs}$。对于某个 Token 对应的质心 $i$，只有当其与查询的最大相似度 $\max(S_{c,q_i}) \ge t_{cs}$ 时，该 Token 的质心才被保留用于后续计算；否则直接丢弃。
  - **效果**：大幅稀疏化文档的"质心袋"表示，减少阶段 3 的矩阵构建开销。

- **阶段 3：质心交互（Centroid Interaction）**
  - **核心**：利用观察 1，用"质心袋"近似替代"原始向量"进行打分。
  - **操作**（公式 3 & 4）：
    1. 对于阶段 2 筛选后的候选文档，取出其存储的质心 ID 列表 $I$。
    2. 直接复用阶段 1 计算好的 $S_{c,q}$ 矩阵，构建**近似文档矩阵** $\tilde{D}$。
    3. 对 $\tilde{D}$ 执行轻量级的 **MaxSim** 求和操作，得到近似得分 $S_{\tilde{D}}$。
  - **输出**：根据近似得分排序，截取排名靠前的 `ndocs` 篇文档（论文设定 `ndocs` 对应最终返回 $k$ 的 4 倍，即若返回 1000 篇，则此阶段保留 4096 篇）。

- **阶段 4：精确重排与打分（Exact Scoring with Decompression）**
  - 仅对阶段 3 留下的极少数量（`ndocs`）文档执行**完整的残差解压（Residual Decompression）**，重建出原始浮点向量矩阵 $D$。
  - 执行标准 ColBERT 的精确 **MaxSim** 计算（公式 1）：
    $$
    S_{q,d} = \sum_{i=1}^{|Q|} \max_{j=1}^{|D|}(Q_i \cdot D_j^T)
    $$
  - 按最终精确得分排序，返回 Top-$k$ 结果。

---

#### 4. 工程级深度优化（System-Level Optimizations）

除了算法层面的筛选，PLAID 在底层计算上进行了两项关键的重构：

- **4.1 无填充 MaxSim 内核（Padding-Free MaxSim Kernel）**
  - **痛点**：原始 ColBERTv2 为利用 PyTorch 的批处理（Batched）矩阵乘法，需将变长的文档向量强行填充（Padding）至统一最大长度，生成巨大的 3D 张量，严重浪费显存/内存和计算带宽。
  - **PLAID 方案**：采用自定义 C++ 多线程代码，直接遍历"压紧（Packed）"的 2D 索引张量（各文档向量首尾相连）。针对每个文档，仅分配 $O(|Q|)$ 的临时内存，就地更新 Max 值。
  - **效果**：彻底消除填充开销，且 CPU 上内存占用大幅降低。（注：该优化当前仅实现于 CPU，GPU 版本为未来工作。）

- **4.2 查表式残差解压（Lookup-based Decompression）**
  - **痛点**：ColBERTv2 使用 1-bit 或 2-bit 存储残差维度。原始解压需要执行大量的位运算（Bit shifting）、掩码操作和加法，极其耗时（图 2a 显示其占比极高）。
  - **PLAID 方案**：由于 8-bit（1 字节）内存储了固定数量的索引（如 2-bit 存 4 个索引），PLAID 在运行时**预计算**出一个包含所有 $2^8 = 256$ 种可能情况的解压结果查找表（Lookup Table, LUT）。
  - **操作**：解压时，不再进行位运算，而是直接以该字节数值为下标，从 LUT 中**复制**出预先算好的浮点残差值。
  - **实现**：CPU 端以"文档"为粒度并行查表；GPU 端（CUDA）以"单个字节"为粒度启动数千个线程并行查表，极致压榨并行能力。

#### 5. PLAID 核心成果总结

| 维度 | ColBERTv2（原始） | **PLAID ColBERTv2（本论文）** |
| :--- | :--- | :--- |

## DESSERT: An Efficient Algorithm for Vector Set Search with Vector Set Queries

> DESSERT（DESSERT Efficiently Searches Sets of Embeddings via Retrieval Tables）是首个专为**向量集合搜索（Vector Set Search）** 设计的可扩展算法。它基于**局部敏感哈希（LSH）**，将昂贵的浮点数点积运算转化为极快的整数哈希查找和碰撞计数。当集成到ColBERT中时，DESSERT在MS MARCO和LoTTE检索基准上实现了比PLAID快 **2-5倍** 的端到端加速，同时仅损失极少的召回率。

---

#### 1. 核心动机与关键观察（Motivation & Insights）

在深入技术细节前，DESSERT的设计源于对传统检索范式的深刻反思：

- **观察 1：单向量ANN无法处理集合级语义（论文 Section 1.2）**
  - 传统近似最近邻（ANN）搜索针对的是**单个向量**。若将文档中的所有Token向量拆开存入ANN索引，查询时某个词（如“苹果”）会匹配到任何包含“苹果”的文档，完全忽略文档中其余词（如“手机” vs “水果”）的上下文，导致语义漂移。
  - 此外，若每篇文档有1000个Token，1百万篇文档将产生10亿个向量，ANN索引规模失控。

- **观察 2：集合相似度具有可分解的"内层聚合"结构（论文 Section 1.1）**
  - ColBERT的评分函数 $F(Q, S) = \sum_{q \in Q} \max_{x \in S} \text{sim}(q, x)$ 是典型的"集合到集合"评分。
  - 这种结构允许将"计算相似度"与"聚合"解耦。DESSERT利用这一点，**先快速估算所有Token对的相似度（通过LSH碰撞），再执行Max和Sum聚合**。

- **观察 3：LSH碰撞频率是相似度的无偏估计**
  - 通过选择合适的LSH函数族，两个向量的哈希碰撞概率 $p$ 精确等于它们的相似度 $\text{sim}(x, y)$。因此，重复 $L$ 次独立哈希实验，碰撞频率 $ \hat{p} = \text{count} / L $ 即可作为相似度的可靠估计。

---

#### 2. 核心概念：局部敏感哈希（LSH）与碰撞计数

**LSH函数定义（论文 Section 3）**：
假设存在哈希函数族 $\mathcal{H}$，对于任意向量 $x, y$，满足：
$$ p(h(x) = h(y)) = \text{sim}(x, y) $$
其中 $\text{sim}$ 是余弦相似度等度量（论文使用余弦相似度，通过符号随机投影实现）。

**核心计数机制**：
- 对于查询向量 $q$ 和目标向量 $x$，使用 $L$ 个独立的LSH函数进行哈希。
- 统计 $q$ 与 $x$ 发生"碰撞"（哈希值相等）的次数 $c$。
- 则相似度估计值为：$\hat{s} = c / L$。
- 当 $L$ 足够大时，$\hat{s}$ 依概率收敛于真实相似度。

---

#### 3. 离线索引构建（Indexing Pipeline）

> 目标：将原始文档集合压缩成高度紧凑的**草图（Sketch）** 结构，支持极速的碰撞查询。

- **3.1 参数设定**
  - 设定哈希表数量 $L$（如 32 或 64）。
  - 设定**拼接宽度（Concatenation Width）** $C$（如 6 或 7），用于解决哈希桶过满问题（详见优化章节）。
  - 对全量文档中的Token向量进行 K-Means 聚类（用于后续过滤步骤）。

- **3.2 向量哈希与草图填充（Algorithm 1）**
  - 对文档 $S_i$ 中的每个向量 $x_j$（$j$ 为文档内局部索引）：
    1. 使用 $L$ 个复合LSH函数（每个由 $C$ 个子哈希拼接而成）计算哈希值。
    2. 将局部索引 $j$ 存入该文档对应的草图 $\mathcal{D}[i]$ 中。
  - **存储结构**：$\mathcal{D}[i]_{t, h} = \{ j \mid f_t(x_j) = h \}$，表示"在第 $t$ 个哈希表下，值为 $h$ 的桶内包含的向量索引集合"。

- **3.3 构建过滤倒排索引（Filtering Inverted Index）**
  - 同时，将每个向量 $x_j$ 分配到距离最近的 K-Means 聚类中心。
  - 构建映射：`聚类中心ID -> 文档ID列表`。
  - 此索引用于查询时快速筛选出少量候选文档（过滤掉 99% 的不相关文档）。

- **3.4 存储优化：TinyTable（论文 Section 5）**
  - **痛点**：若每个文档用标准哈希表（`std::unordered_map`）存储，空桶占用巨大（$N \times L \times \text{range}$ 可达上百GB）。
  - **DESSERT方案**：设计 **TinyTable**。
    - 将每个哈希表分为两部分：**偏移量列表（Offset List）** 和 **向量ID列表（Vector ID List）**。
    - 偏移量指示每个桶在ID列表中的起始和结束位置（空桶用相同偏移量表示）。
    - 将所有 $L$ 个表的偏移量和ID列表分别**拼接（Concatenate）** 存储。
    - 当文档长度 $m \le 256$ 时，使用 `uint8_t`（单字节）存储偏移量和ID，极大压缩内存。
  - **空间对比**：对于 $N=1M, L=64, m=100$ 的场景，TinyTable内存占用仅 **14.7 GB**（而朴素实现需 196 GB）。

---

#### 4. 在线查询处理（Query Pipeline）

> 目标：通过"过滤粗筛 + LSH碰撞估算"两阶段，极速返回最相关的Top-K文档。

- **4.1 查询向量化**
  - 对输入查询 $Q$（包含 $m_q$ 个Token向量）进行编码。
  - 同样计算每个查询向量的 $L$ 个复合LSH哈希值。

- **4.2 阶段一：基于聚类的候选过滤（Filtering）**
  - 对每个查询向量，找到最近的 `filter_probe` 个聚类中心。
  - 查倒排索引，聚合所有命中文档ID，得到候选文档计数。
  - 按计数降序排序，取前 `filter_k` 篇文档（如 4096 篇）作为候选集，进入下一阶段。

- **4.3 阶段二：DESSERT精确估算打分（Algorithm 2）**
  - 对于候选集中的每篇文档 $S_i$，执行以下循环（极度高效）：
    1. **遍历查询向量**：对于 $Q$ 中的每个 $q$。
    2. **遍历哈希表**：对于 $t = 1$ 到 $L$。
    3. **查桶取数**：根据 $q$ 的哈希值 $h_{t,q}$，直接访问 $\mathcal{D}[i]_{t, h_{t,q}}$，获取当前桶内的所有文档局部索引 $j$。
    4. **增量计数**：对这些索引 $j$ 的计数器加 1。
  - **结束内层循环后**：对于文档 $S_i$ 中的每个向量 $x_j$，计数器值 $c_j$ 表示与 $q$ 的碰撞次数。
  - **还原相似度**（去拼接）：
    $$ \hat{s}_j = \left( \frac{c_j}{L} \right)^{\frac{1}{C}} $$
    （因为拼接后碰撞概率变为 $\text{sim}^C$，开 $C$ 次方还原）。
  - **应用聚合函数**：
    - 内层聚合（Max）：$\text{agg}_q = \max_j \hat{s}_j$。
    - 外层聚合（Sum）：$\text{score}_i = \sum_{q \in Q} \text{agg}_q$。

- **4.4 排序与返回**
  - 根据估算得分 $\text{score}_i$ 对候选文档降序排序。
  - 返回 Top-K 结果。

---

#### 5. 核心工程优化（System-Level Optimizations）

- **5.1 拼接技巧（Concatenation Trick，论文 Section 5）**
  - **问题**：若直接用单LSH，余弦相似度 0.3 意味着每个桶装 30% 的向量，毫无区分度。
  - **解法**：将 $C$ 个独立的LSH子哈希值拼接成一个复合键（如 `hash1|hash2|...`）。碰撞概率降为 $\text{sim}^C$，桶内元素数量骤减（如 $0.3^6 \approx 0.0007$）。
  - **运行时**：碰撞计数 $c$ 最大为 $L$，相似度估计为 $\hat{p}^{1/C}$。因 $c$ 只有 $L+1$ 种可能，预先计算好映射表（Lookup Table），查询时直接查表，无需运行中开方或对数运算。

- **5.2 向量化及内存布局（Vectorization & Memory Layout）**
  - 所有草图中的TinyTable数据在内存中连续紧凑排列，具备良好的缓存局部性。
  - 查询时，对于大批量候选文档，CPU预取指令能高效加载连续内存区域。

- **5.3 C++ 高性能实现**
  - 论文提供开源C++实现，支持多线程并行。
  - 查询循环中无动态内存分配，所有计数器数组预先分配并复用。

---

#### 6. 理论保证（Theoretical Guarantees，论文 Section 4）

- **6.1 正确性概率（Theorem 4.2）**
  - 假设真实最优集合 $S^*$ 与次优集合的得分差至少为 $\Delta > 0$。
  - 设定哈希表数量：
    $$ L = O\left( \log\left( \frac{N \cdot m_q \cdot m}{\delta} \right) \right) $$
  - 则DESSERT能以至少 $1 - \delta$ 的概率正确返回最优集合 $S^*$。

- **6.2 查询时间复杂度（Theorem 4.3）**
  - 假设每个哈希桶的大小有界（不超过常数 $T$）。
  - 则查询时间复杂度为：
    $$ O\left( m_q \log(N m_q m / \delta) \cdot d + m_q N \log(N m_q m / \delta) \right) $$
  - 相比暴力搜索的 $O(m_q m N d)$，当文档长度 $m$ 或向量维度 $d$ 较大时，DESSERT具有显著的渐进优势。

## EMVB: Efficient Multi-Vector Dense Retrieval Using Bit Vectors（高性能多向量检索引擎）

---

#### 1. 核心动机与关键观察（Motivation & Critical Observations）

在深入技术细节前，EMVB 的设计源于对 PLAID 执行时间的细粒度剖析（论文图 1）以及两个关键的数据分布洞察：

- **瓶颈分析（PLAID 执行时间拆解）**：
  - **候选生成（Retrieval）**：PLAID 中提取 Top-$nprobe$ 质心的 `quickselect` 算法开销巨大，其成本甚至高达矩阵乘法的 **3 倍**。
  - **质心交互（Centroid Interaction）**：当候选文档数 $k$ 较大时，此阶段成为主要瓶颈。
  - **残差解压（Decompression）**：PLAID 的 1-bit/2-bit 解压成本极其昂贵，其延迟是后期交互（Late Interaction）阶段的 **5 倍**。
- **观察 1：质心得分的长尾分布（图 2 左）**
  - 对于给定的查询，大部分文档质心的相似度得分极低。实验表明，设置一个较低的阈值（如 $th = 0.4$），即可在不损失 R@100 召回率的前提下，将候选文档集从数万级缩减至仅 **1000 篇**。
- **观察 2：MaxSim 由质心主导（图 5）**
  - 在公式 $q_i \cdot T_j = q_i \cdot \bar{C} + q_i \cdot r$ 中，质心部分（$q_i \cdot \bar{C}$）往往远大于残差部分（$q_i \cdot r$）。因此，**超过 30% 的残差计算可以安全跳过**，而完全不影响最终 MRR@10 指标。

---

#### 2. 离线索引构建：乘积量化（Product Quantization）替代残差压缩

> 核心思想：抛弃 PLAID 复杂且解压缓慢的 1-bit/2-bit 残差压缩，改用工业界成熟的 **乘积量化（PQ）** 技术，实现“不解压直接计算点积”。

- **2.1 向量生成（与 ColBERTv2 一致）**
  - 使用 ColBERTv2 模型将文档 Token 编码为 128 维浮点数向量。
  - 采用 K-Means 聚类生成质心集合（$|C| = 2^{18}$）。

- **2.2 JMPQ 量化（联合优化乘积量化）**
  - **替代对象**：PLAID 存储 `质心 ID + 1/2-bit 残差`（约 36 字节/向量）。
  - **EMVB 方案**：引入 **JMPQ（Joint optimization of Multi-vector representation with Product Quantization）**。
    - 将 128 维残差向量分割为 $m$ 个子空间（实验采用 $m=16$ 或 $m=32$）。
    - 对每个子空间独立进行聚类，生成码本（Codebook）。
    - 向量被存储为：`质心 ID (4 字节) + PQ 码 (m 字节)`。
  - **内存对比**：
    - $m=16$ 时，每个向量仅占 **20 字节**，相比 PLAID（36 字节）减少 **1.8 倍**。
    - $m=32$ 时，与 PLAID 内存持平（36 字节），但精度更高。

- **2.3 倒排索引与位向量结构**
  - 保留 PLAID 的倒排索引：`质心 ID -> 文档 ID 列表`。
  - **额外构建（核心创新 1 的数据基础）**：为支持极速预过滤，离线阶段将每个文档的质心 ID 列表 $I_P$ 以紧凑的 32 位整型数组存储，等待查询时进行位运算匹配。

---

#### 3. 在线查询处理：四阶段极致加速流水线（The 4-Stage Pipeline）

> EMVB 重新设计了 PLAID 的流水线，将“候选生成”与“质心交互”前置并通过位向量和 SIMD 指令进行极致加速。

- **阶段 0：查询编码与质心得分计算**
  - 对查询 $Q$ 编码为 32 个 Token 向量（$n_q = 32$）。
  - 执行矩阵乘法 $CS = Q \cdot C^T$，得到 $32 \times 262144$ 的浮点得分矩阵。

- **阶段 1：基于位向量的超高速预过滤（创新点 1）**
  - **痛点**：PLAID 在此处执行昂贵的 `quickselect` 提取 Top-$nprobe$。
  - **EMVB 操作**：
    1. **阈值过滤**：设定阈值 $th$（如 0.4）。对于查询词 $q_i$，筛选出 $CS$ 中得分 $> th$ 的质心集合 $\text{close}_i^{th}$。
    2. **无分支向量化选择**：使用 AVX-512 指令 `_mm512_cmp_epi32_mask` 一次性比较 16 个浮点数，配合 `_mm512_mask_compressstore` 无分支地将满足条件的索引紧凑写入缓冲区，彻底消除 CPU 分支预测失败带来的 10ns 延迟。
    3. **垂直堆叠位向量（Vertical Stacking）**：
       - 将 32 个查询词的 $\text{close}_i^{th}$ 集合按**质心 ID** 垂直堆叠。即内存中连续存放的是“某个质心 ID 对应所有 32 个查询词的命中情况（32-bit 字）”。
       - 遍历文档的质心 ID 列表 $I_P$，取出对应的 32-bit 字，执行 `xor` 和 `popcnt`（`_mm_popcnt_u32`）指令，极速计算该文档命中了多少个查询词（公式 4）。
  - **效果**：此预过滤步骤比 PLAID 的原生质心交互快 **30 倍**（图 4），且无损召回。

- **阶段 2：SIMD 列归约加速质心交互（创新点 2）**
  - **痛点**：PLAID 按行处理质心得分矩阵，内存访问不连续。
  - **EMVB 操作**：
    1. **矩阵转置**：将 $CS$ 转置为 $CS^T$（形状 $|C| \times 32$），确保同一文档的质心得分在内存中连续存放，缓存命中率提升 2 倍以上。
    2. **SIMD 寄存器归约**：
       - 由于 $n_q = 32$，利用 **2 个 AVX-512 寄存器**（各存 16 个 float）即可容纳一行数据。
       - 采用 `_mm512_cmp_ps_mask` 比较 `max` 与 `curr` 寄存器，使用 `_mm512_mask_blend_ps` 更新最大值。得益于 IceLake 架构的并行端口，每处理一行仅需 **2 个时钟周期**。
  - **效果**：该阶段比 PLAID 的过滤实现快 **1.8 倍**（图 4 下）。

- **阶段 3：基于 PQ 的无解压后期交互（创新点 3）**
  - **痛点**：PLAID 需要昂贵的位运算解压残差（图 1 显示解压耗时是打分的 5 倍）。
  - **EMVB 操作**：利用 PQ 的数学性质，将点积分解为：
    $$S_{q,P} = \sum_{i=1}^{n_q} \max_{j} (q_i \cdot \bar{C}^{T_j} + q_i \cdot r_{pq}^T)$$
    - 第一部分（$q_i \cdot \bar{C}$）直接从阶段 2 的矩阵复用。
    - 第二部分（$q_i \cdot r_{pq}$）通过 **PQ 查表（Look-up Table）** 直接获取，**完全跳过浮点数解压和矩阵乘法**。
  - **效果**：后期交互延迟比 PLAID 的 $b$-bit 压缩器快 **3.6 倍**。

- **阶段 4：动态文档项过滤（创新点 4）**
  - **观察**：很多 Token 的残差点积对最终 Max 值无影响（质心得分已足够高）。
  - **操作**：引入第二阈值 $th_r = 0.5$。仅当 $q_i \cdot \bar{C}^{T_j} > th_r$ 时，才计算残差项 $q_i \cdot r_{pq}^T$（否则只保留质心得分）。
  - **效果**：在完全不损失 MRR@10 的前提下，将阶段 3 中需要计算残差的 Token 数量减少了 **至少 30%**（图 5）。

#### 4. 工程级深度优化（System-Level Optimizations）

- **4.1 无分支（Branchless）预过滤算法**
  - 传统的 `if` 判断会导致 15-20 个时钟周期的流水线冲刷。EMVB 使用 `compressstore` 指令实现条件写入，使执行流恒定，无论阈值如何变化，耗时保持稳定（图 2 右）。

- **4.2 内存连续性与对齐**
  - 所有位向量、质心得分矩阵、PQ 码本在内存中均按 64 字节对齐，确保 AVX-512 指令能以单次加载读取完整 Cache Line，避免 TLB 缺失。

- **4.3 查表式 PQ 得分计算**
  - 与 PLAID 的查表解压类似，EMVB 针对 PQ 子空间预先计算查询子向量与所有码字的点积表，评分时直接通过 PQ 码下标取值并累加，计算复杂度仅为 $O(m)$ 次整数访问和加法。

## WARP: An Efficient Engine for Multi-Vector Retrieval（高性能多向量检索引擎）

---

## 1. 核心动机与关键观察（Motivation & Critical Observations）

WARP 的设计源于对现有两大 SOTA 系统——**XTR/ScaNN** 与 **ColBERTv2/PLAID** 的深入剖析，旨在融合两者优势并解决各自的根本性瓶颈。

- **XTR 的潜力与缺陷**：
  - XTR 通过“Token 检索”机制，省去了传统 ColBERT 中的显式候选聚合（Gathering）阶段，理论上简化了流程。
  - 但其官方实现依赖通用向量库 **ScaNN** 和纯 Python 数据结构，单线程端到端延迟在 LoTTE Pooled 上超过 **6 秒**，无法投入生产。
  - 瓶颈集中在两处：**Token 检索**（ANN 开销巨大）和 **未优化的打分循环**（Python 迭代极慢）。

- **PLAID 的效率与局限**：
  - PLAID 通过四阶段流水线（生成 → 剪枝 → 质心交互 → 精确重排）将 ColBERTv2 延迟降至数百毫秒。
  - 但其**残差解压（Decompression）** 阶段开销极高（占 150–200 ms），且在小数据集上 Query 编码成为新瓶颈。
  - 更重要的是，PLAID 的“质心交互”与 XTR 的“缺失相似度估计”在数学上存在互补性，但现有工作未将其结合。

- **关键洞察**：
  1. **质心得分可复用**：在候选生成阶段已计算 Query 与所有质心的相似度矩阵 $S_{c,q}$，该矩阵既能用于检索，也能用于估计 XTR 所需的缺失相似度。
  2. **解压可与打分融合**：PLAID 的解压和后续 MaxSim 计算是串行的，但数学上可将解压公式展开，直接计算点积而无需显式重建向量。
  3. **归约可两阶段完成**：XTR 的评分函数可分解为 Token 级 Max 归约和 Document 级 Sum 归约，无需构建完整得分矩阵。

基于以上观察，WARP 提出了三项核心创新，在**保持甚至提升检索精度的前提下**，实现端到端延迟比 XTR 快 **41 倍**，比 PLAID 快 **3 倍**。

---

## 2. 索引构建（Index Construction）

WARP 的索引结构借鉴 ColBERTv2 的残差压缩，但针对 XTR 的评分特点进行了定制。

### 2.1 向量编码与聚类
- 使用 XTR 模型（基于 T5）将文档编码为 Token 级向量，维度 $d = 128$。
- 从文档集合中采样（采样数量正比于 $\sqrt{N}$），对采样向量执行 **K-Means 聚类**，得到 $n_c$ 个质心 $\{c_1, \dots, c_{n_c}\}$，其中 $n_c \propto \sqrt{N}$。

### 2.2 分位数量化残差（Quantile-based Residual Quantization）
- 对每个 Token 向量 $v$，找到最近的质心 $c_t$，计算残差 $r = v - c_t$。
- 对残差的**每一维**独立进行量化，使用 **分位数（Quantile）** 而非均匀量化：
  - 统计所有残差在每一维上的经验分布，确定 $2^b$ 个分位点作为 bucket 边界。
  - 每个维度用 $b$ 位（通常 $b=4$）存储对应的 bucket 索引。
- **存储内容**：
  - 质心 ID（4 字节）。
  - 量化残差：$128 \times (b/8)$ 字节（例如 $b=4$ 时为 64 字节）。
- **优势**：分位数量化使 bucket 在数据密集区域更精细，量化误差更小，从而在同等压缩率下保留更高精度。

### 2.3 倒排索引
- 构建映射：`质心 ID -> 归属于该质心的文档 Token 列表`（存储文档 ID 和局部索引）。
- 此倒排结构与 PLAID 一致，为后续快速候选生成提供支持。

---

## 3. 在线检索：四阶段流水线（The 4-Stage Pipeline）

WARP 的在线检索分为四个阶段：**Query 编码 → 候选生成（含 WARP SELECT）→ 隐式解压打分 → 两阶段归约排序**。

### 3.1 Query 编码
- 将 Query 文本输入 XTR 模型，得到 $n_q$ 个 Token 向量（通常 $n_q \le 32$），经 L2 归一化后得到矩阵 $Q \in \mathbb{R}^{n_q \times 128}$。
- 使用优化的推理运行时（如 ONNX Runtime）加速编码过程。

---

### 3.2 候选生成（WARP SELECT）
**目标**：为每个 Query Token 选择 $n_{\text{probe}}$ 个最相关的质心，并同时估计缺失相似度。

#### 3.2.1 质心得分计算
- 计算 Query 与所有质心的余弦相似度（点积，因均已归一化）：
  $$ S_{c,q} = C \cdot Q^T \quad \text{其中 } C \in \mathbb{R}^{n_c \times 128} $$
  得到矩阵 $S \in \mathbb{R}^{n_c \times n_q}$。

#### 3.2.2 选择 Top-$n_{\text{probe}}$ 质心
- 对每个 Query Token $q_i$，从 $S$ 中取出第 $i$ 列，选择得分最高的 $n_{\text{probe}}$ 个质心索引。
- 通过倒排索引，获取这些质心下的所有文档 Token，形成初始候选集（规模较大，后续阶段会缩减）。

#### 3.2.3 WARP SELECT（动态缺失相似度插补）
这是 WARP 的核心创新之一，用于估计 XTR 评分公式中的缺失项 $m_i$（Equation 1）。

- **传统 XTR**：$m_i$ 设为 Token 检索阶段得到的最低得分，但该值依赖较大的检索量 $k'$，且不适用于剪枝。
- **WARP 方案**：
  1. 对于 Query Token $q_i$，将其与所有质心的得分 $S[:, i]$ **降序排列**。
  2. 按顺序累加每个质心所包含的文档 Token 总数（即集群大小）。
  3. 当累加大小**首次超过阈值** $t'$ 时，停止，并将当前质心的得分设为 $m_i$。
- **参数设置**：$t'$ 设置为 $\sqrt{\text{数据集大小}}$，实验表明该配置在所有数据集上均表现鲁棒。
- **效果**：该估计完全复用已计算的 $S$ 矩阵，额外开销可忽略，且比 XTR 的原始方法更稳定（精度无损）。

---

### 3.3 隐式解压与打分（Implicit Decompression & Scoring）
**目标**：计算每个候选 Token 与 Query Token 的点积，但**避免显式重建浮点向量**。

#### 3.3.1 数学分解
对于候选 Token $v$，其存储为 `(质心 $c_t$, 残差 $r$)`。点积可展开为：
$$ q_i \cdot v = q_i \cdot c_t + q_i \cdot r $$
- 第一项 $q_i \cdot c_t$：已在阶段 3.2.1 计算好的 $S$ 矩阵中，可直接复用。
- 第二项 $q_i \cdot r$：需从量化残差中获取。

#### 3.3.2 查表法（Lookup Table）计算残差点积
- 对于每个 Query Token $q_i$，预计算一个查找表 $T_i$，其大小为 $2^b$（例如 $b=4$ 时为 16），其中
  $$ T_i[k] = \sum_{d=1}^{128} \omega_d[k] \cdot q_{i,d} $$
  这里 $\omega_d[k]$ 是第 $d$ 维 bucket $k$ 的代表值（分位数）。
- 对于残差 $r$ 的每一维，其存储的 bucket 索引 $idx_d$ 直接作为下标查表，得到贡献值 $T_i[idx_d]$。
- 对所有 128 维求和，即得 $q_i \cdot r$。
- **关键**：整个过程**无需解压出浮点数向量**，仅需整数索引访问和累加，且所有乘法在查表阶段一次性完成。

#### 3.3.3 得分生成
最终 $q_i$ 与 Token $v$ 的相似度为：
$$ \text{score}(q_i, v) = S[c_t, i] + \sum_{d=1}^{128} T_i[(r)_d] $$
此步骤在 WARP 的 C++ 内核中实现，使用位运算快速提取残差索引，并在寄存器内完成累加。

---

### 3.4 两阶段归约（Two-Stage Reduction）
**目标**：将 Token 级得分聚合为文档级分数，同时处理缺失值。

#### 3.4.1 Token-Level 归约（Max 归约）
- 对每个 Query Token $q_i$，遍历候选文档中所有属于 $q_i$ 所选质心的 Token 得分，取最大值。
- 形式上，定义文档 $d$ 在 Token $q_i$ 上的得分为：
  $$ \text{maxSim}_i(d) = \max_{v \in \text{Tokens}(d) \cap \text{candidates for } q_i} \text{score}(q_i, v) $$
- 若文档 $d$ 没有命中任何 Token，则 $\text{maxSim}_i(d) = \bot$（缺失）。

#### 3.4.2 Document-Level 归约（Sum 归约）
- 将所有 $n_q$ 个 Token 的 $\text{maxSim}_i(d)$ 求和，缺失值用 WARP SELECT 估计的 $m_i$ 替代。
- 最终文档得分：
  $$ S_{q,d} = \sum_{i=1}^{n_q} \begin{cases} \text{maxSim}_i(d) & \text{if } \text{maxSim}_i(d) \neq \bot \\ m_i & \text{otherwise} \end{cases} $$
- 此归约使用**前缀和（Prefix Sum）** 技巧和双缓冲区（Double Buffering）高效实现，避免显式构建 $n_{\text{cand}} \times n_q$ 的得分矩阵。

#### 3.4.3 排序输出
- 对候选文档按最终得分降序排序，使用堆选择（Heap Select）返回 Top-$k$ 结果。

---

## 4. 工程级深度优化（System-Level Optimizations）

### 4.1 专用 C++ 内核
- WARP 的核心计算（候选生成、隐式解压、归约）全部用 C++ 实现，并利用 **AVX2** 指令集进行向量化。
- 位操作（提取残差索引）采用无分支（Branchless）设计，消除分支预测失败。

### 4.2 内存布局与缓存优化
- 倒排列表、质心矩阵、查询得分矩阵均按 **64 字节对齐**，确保每次内存访问命中 Cache Line。
- 采用**连续紧凑存储**（如将残差按字节流打包），提高预取效率。

### 4.3 多线程并行化
- WARP 的检索过程可在多线程下高效扩展：
  - 候选生成阶段将 Query Token 分发给不同线程，并行计算质心得分。
  - 隐式解压和归约阶段按文档块划分，线程间负载均衡。
- 在 16 线程下，LoTTE Pooled 获得 **3.1 倍加速**（相比单线程）。

### 4.4 参数自适应
- $n_{\text{probe}}$：实验表明设置为 32 可在精度与速度间取得最优平衡（图 6）。
- $t'$：自动设为 $\sqrt{N}$，并限制上限 $t'_{\max}$ 防止过估。
- $b$：默认 4 位量化，提供 8 倍压缩且精度损失极小（图 7）。
